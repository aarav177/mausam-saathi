# Mausam Saathi — SIH26086 farmer advisory portal

This portal reads the project's existing Palwal village boundaries and trained
model evaluation outputs. It does not modify the source dataset. The records
currently available are historical (through 2025), not a live 2026 forecast;
the UI labels them accordingly and does not present them as current alerts.

## Run locally

1. Revoke any API key that has been exposed in chat or elsewhere. Create a
   replacement in the OpenRouter dashboard; do not paste it into source code,
   a frontend setting, or a chat message.
2. From this folder, copy `.env.example` to `.env` and add your provider key.
   Set `OPENROUTER_API_KEY` and keep `OPENROUTER_MODEL=openrouter/free`.
   The portal sends AI requests only to OpenRouter; it does not use an
   `OPENAI_API_KEY`. `.env` is ignored by Git. The key is used by the Python
   backend only and is never sent to the browser.
3. Install portal packages: `pnpm install`
4. Install backend packages with the project's selected Python:
   `python -m pip install -r backend/requirements.txt`
5. Terminal 1, start the backend from this folder:
   `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000`
6. Terminal 2, start the portal: `pnpm dev`
7. Open the Vite URL printed in the terminal (normally
   `http://localhost:8443`). The Vite dev server proxies `/api` calls to the
   local backend.

Create a local portal account with a name, username, and password. A phone
number and interest in future SMS alerts are optional. The phone and preference
are stored locally, but SMS delivery is not active until a provider and live
alert source are configured. Accounts and password hashes are stored in an
ignored local SQLite database; the session-signing secret is stored locally
and is never committed. Each visit starts with a skippable, illustrated
farmer introduction of about 16 seconds with captions and spoken narration.
Hindi and Haryanvi narration use bundled audio; Haryanvi is spoken with a
Hindi neural voice. English narration uses an installed browser voice. After
sign-in, a read-aloud control is available on every portal page. The portal
supports Hindi, English, and Haryanvi.

After signing in, use the separate Home, Village dashboard, Weather insights,
Farmer assistant, Notifications, and My profile pages. Home is a simple
welcome/navigation page. On Weather insights, select a village and a 7-, 14-,
21-, or 30-day period, then choose a crop and growth stage and optionally
describe a field concern. The portal requests a day-by-day field-check plan from
OpenRouter automatically after the selections are complete or changed; no
separate submit button is needed. Profile edits are saved to the local account.
The Notifications page shows the saved SMS preference and service availability;
it does not claim that SMS or live weather alerts are being delivered.

The AI's day-by-day output is a general crop/stage field-check plan, not a
daily weather forecast. The available project outlook is historical and only
provides aggregate event likelihoods and a period rainfall estimate; it does
not supply daily future weather. These are not prescriptions; irrigation,
chemical use, and other field decisions should be based on current local
conditions and advice from an agriculture officer or KVK.

The dashboard/map work without an AI key. Farmer Q&A exclusively uses the
configured OpenRouter free-model router and reports clear key, provider, and
rate-limit errors. OpenRouter free models can be busy or rate-limited; retry or
choose another model listed in your OpenRouter account.
A working map also needs internet access for OpenStreetMap tiles. Village
outlines come from the local project GeoJSON file; block boundaries/assignments
are not claimed.

## Model and advisory boundaries

- Select a Palwal village and 7/14/30-day horizon to inspect historical
  break, onset-proxy, and revival probabilities plus the stored rainfall
  model's historical estimate.
- The rainfall estimate is a historical **period total**, not daily weather
  or a forecast of upcoming rainfall.
- Stored event scores are historical model likelihood estimates, not
  confidence scores, live forecasts, or official IMD warnings.
- Daily crop guidance is generated by OpenRouter and must not invent daily
  weather, rainfall, or event probabilities.
- The AI answers in short, plain language with a direct response and practical
  steps, tailored to the selected crop and growth stage. It explains project
  model outputs as historical event likelihoods, not confidence scores or
  current weather. It is not the prediction engine or an official agronomist.
- Do not deploy publicly without authentication, rate limiting, HTTPS,
  operational monitoring, and current validated forecast inputs.

## Fit to SIH26086 problem statement

The portal demonstrates village-level monsoon-risk visualization using the
project's 281 mapped Palwal villages and nearest-cell IMD rainfall data. It
offers the 7, 14, 21, and 30-day historical evaluation horizons for break,
rainfall-onset proxy, and revival events. The onset target is a project rainfall
proxy, not official IMD onset ground truth. Probability bands are project
thresholds, not official warnings. Nearby villages can share a 0.25-degree
rainfall grid cell.

These displayed outputs are historical evaluation records through 2025. The
trained rainfall features include same-day end-of-day observations, so the
outputs are not ready to issue as a pre-sowing operational forecast. Heavy-rain
classification was not trained because the 2023 validation split contained no
positive cases. No heavy-downpour risk is shown.

The problem statement's wider operational requirements are not yet met:

- **Block forecasts:** village-to-block assignments are blank; no block
  aggregation is claimed.
- **ENSO/IOD/MJO inputs:** source definitions and point-in-time availability
  have not been verified, so these signals are excluded from model features.
- **Operational GFS/ECMWF downscaling:** the saved GFS file is one short-lead
  sample from 2026-10-07; the saved ECMWF/AIFS sample has zero forecast lead.
  Neither is a current forecast feed or integrated into the historical model.
- **Crop advisories:** the assistant provides general AI-generated guidance
  from selected crop/stage and project context. It is not a validated,
  deterministic agronomy rules engine or an official recommendation.
- **SMS/WhatsApp alerts:** the profile stores a farmer's interest only. No
  messaging provider, alert trigger, or live forecast feed is configured.

The next technical steps are to verify point-in-time climate data, obtain
current multi-lead forecast cycles and an authoritative village/block
crosswalk, build and backtest a forecast-time-safe model, validate agronomy
rules with local experts, and only then configure alert delivery.

## Portal code map

Start here when changing the application:

- `src/main.tsx` mounts the React application and imports the portal stylesheet.
- `src/PortalApp.tsx` contains page state, translations, API calls, and the
  authenticated farmer pages.
- `src/WelcomeIntro.tsx` is the language-aware welcome screen and reads its
  mapped-area summary from `/api/coverage`.
- `src/welcome.css` styles the welcome page separately from signed-in portal
  pages, including its phone layout.
- `src/AuthScreen.tsx` contains sign-in and account creation.
- `src/PortalIcon.tsx` is the shared outline icon set used across portal pages.
- `src/portal.css` holds global, component, and responsive styles.
- `backend/app.py` provides authentication, village/model data, and AI endpoints.
- `public/` contains browser assets such as the site icon and welcome audio.

The numbered folders beside this portal hold the data pipeline. The current
portal inputs are `02_GIS/processed/palwal_villages.csv`,
`02_GIS/palwal/palwal_villages.geojson`, `10_RISK_ENGINE/village_risk.csv`,
and `09_PREDICTIONS/future_rainfall_predictions.csv`. They currently cover
Palwal only. To add a district, connect and validate its village list,
boundaries, and matching model outputs together; the wider Haryana source
boundary file alone does not provide district-level risk results.

`node_modules/`, `dist/`, Python `__pycache__/`, `.env`, and local portal
authentication files are dependencies, generated output, or machine-local
runtime data. They are not source files to reorganize or commit.
